# Architecture

`processBlock` owns oscillator/envelope state, the filter and reverb, and the FIFO read cursor. Parameters are cached atomic pointers. MIDI input is read at event sample offsets; SysEx is skipped without constructing an allocating MIDI message. The callback emits no MIDI and clears consumed input. There is no model loading, file access, session lock or buffer growth on this path. Oversized blocks skip the ONNX layer safely if they exceed the prepared scratch space. Host tempo is bounded to 40–300 BPM; non-finite tempo/PPQ values are ignored.

One worker owns all ONNX session construction, inference, overlap/add state, and the FIFO write cursor. The UI queues model paths under a lock used only outside audio processing. Neither thread resets the FIFO while it is in use. A release/acquire model epoch lets the consumer discard queued samples after a model change. The worker caps the queue near 4096 samples and uses one inference thread. `releaseResources` disables prefill. Inference is paused during offline rendering; an underrun fades the live layer.

Export admission uses compare/exchange before posting work, so repeated clicks cannot enqueue multiple renders. Progress and readiness are atomic. Export sample rate is a separate atomic snapshot; the worker never reads mutable audio-owned sample-rate state. Export settings are read at render start. A cancellable four-bar render writes temporary files, commits complete WAV/MIDI files and only then publishes both paths. UUID filenames prevent second-resolution collisions and overwriting previous exports. Write failures never publish draggable files. The worker is joined before processor destruction; it is never force-killed while using processor state.

The editor starts external file drag after an actual drag gesture and supplies a source component. WAV/MIDI copying is requested, preserving the source exports. File chooser callbacks use a safe component pointer. UI paints at 30 Hz and skips hidden-window scope updates. Actual DAW drag acceptance remains a host test.

ONNX is loaded by an absolute path inside the bundle, with local symbol visibility on macOS and restricted DLL search flags on Windows. No development SDK path is used at runtime. On macOS, a post-build step copies and signs the runtime and bundle. All binaries remain in the build folder until an installer is run.

The test executable checks finite output at five sample rates, sample-offset MIDI input, stopped transport, C++ heap allocation on the callback, parameter state, model inference, WAV bit depth/channels/duration/content, MIDI type/tracks, render admission and failed-write behavior. C++ `new` instrumentation is not a complete malloc or lock profiler. ThreadSanitizer, Instruments, long sessions, CPU/energy profiling and real DAW tests remain separate release checks.
