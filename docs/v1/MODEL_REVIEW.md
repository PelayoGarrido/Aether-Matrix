# Model review — 2026-10-17

The product needs controllable single-instrument **performance MIDI** plus convincing audio. A text-to-audio model with no matched MIDI is not sufficient. These are source-backed screening results, not endorsements or replicated performance claims.

| Candidate | What it contributes | Decision / unresolved issue |
| --- | --- | --- |
| [SkyTNT tv2o-medium](https://huggingface.co/skytnt/midi-model-tv2o-medium) | Small trained MIDI transformer with official ONNX exports; native CPU inference measured here | Evaluation only. Two listed datasets have non-commercial terms; expression/key consistency is unqualified. |
| [Pianist Transformer](https://github.com/yhj137/PianistTransformer) | Learned piano timing, dynamics and pedal from an existing score; 135M parameters, compact asymmetric encoder/decoder | Fixed CPU runtime now executes pinned safetensors locally. Numerical eager-layer/cache checks pass in the tested float32 context. Free timing failed the tested AI scores; constrained decoding passes timing bounds but musical quality and commercial provenance remain unqualified. Its [paper](https://arxiv.org/html/2512.02652v1) lists multiple pretraining corpora and ASAP fine-tuning; permissive model/code labels alone do not settle those rights. It performs score-to-performance, not complete composition-to-audio. |
| [Aria](https://huggingface.co/loubb/aria-medium-base) | Expressive solo-piano continuation and symbolic representations | Author warns of composition memorisation and sensitivity to the input performance. Training-data rights, local resource budget and a generation-specific checkpoint need review; not downloaded. |
| [MIDI-GPT](https://huggingface.co/Metacreation/MIDI-GPT) | Bar/track infill and expressive generation controls | Official published weights are CC-BY-NC-4.0. Not selected for the required commercial route. |
| [text2midi](https://huggingface.co/amaai-lab/text2midi) | Text-conditioned symbolic composition | Corpus rights unresolved; published key/chord-control results are insufficient to assume precise control. Do not execute its remote pickle/code quickstart in the product. Not downloaded. |
| [Stable Audio 3 Small Music](https://huggingface.co/stabilityai/stable-audio-3-small-music) | Local high-fidelity waveform generation, including an Apple implementation | Does not itself deliver a matched editable MIDI performance. Gated conditional licence and download/conversion footprint also need review. Published M4/H200 measurements are not results for this M1. |
| [ACE-Step 1.5](https://github.com/ace-step/ACE-Step-1.5) | Generative audio with current local inference implementations | Does not solve the same-performance MIDI requirement by itself; complete weight/runtime budget and licences need review. Not downloaded. |
| [MusicGen small](https://huggingface.co/facebook/musicgen-small) | Audio generation | Model card labels weights CC-BY-NC-4.0. Not selected for the commercial requirement. |

The credible architecture separates composition, expressive performance and instrument rendering while sharing one editable event representation. Each stage needs independent musical, resource and provenance validation. Adding random velocity jitter or claiming that an ordinary sampler is a neural waveform generator would not meet the requirement.

If no existing model qualifies, the next route is a model trained on a commercially cleared corpus, with documented rights to compositions and performances. That requires real data acquisition and training/evaluation work; a few procedural phrases do not substitute for it. No model was trained from scratch in this iteration.

Dependency review reused JUCE 8.0.16-security and ONNX Runtime 1.31.0. Official public repository advisory API responses contained no published entries on the review date. This does not rule out unpublished vulnerabilities. [JUCE's security policy](https://github.com/juce-framework/JUCE/security) and [ONNX Runtime's release notes](https://github.com/microsoft/onnxruntime/releases/tag/v1.31.0) remain the primary update sources. The first composition evaluation added no package-manager dependency. Stage 2 adds an explicitly authorised isolated Python environment, with all 11 dependency versions/wheel hashes pinned and reviewed against PyPI/OSV. It exposes no HTTP service, uses no cloud inference and disables ONNX/hub telemetry. Native helpers now enforce pinned checkpoint hashes, embedded fixed expression graphs and bounded supervised jobs. External weights remain unbundled; this is process isolation without an OS sandbox, and commercial clearance is still unresolved.

## Stage 2 rights decision

The user authorised non-commercial research/evaluation where applicable terms permit. Free or open-source publication does not waive those terms, and adding datasets does not erase their provenance. No dataset, training recipe or checkpoint is presented as exclusively ours. Permissive weight labels and corpus restrictions are recorded separately: their implications for this product remain unresolved rather than asserted automatically in either direction.

Salamander Grand Piano v3 supplies a commercially usable CC-BY-3.0 recorded-instrument path with attribution, source and modification notices. It does not resolve rights in compositions, training corpora or model outputs. Pianist Transformer is an expressive-stage candidate, not a composition model; the existing three SkyTNT scores retain their original generator provenance. No weights or sample bank are added to public installers.

The JUCE advisory channel was checked again on 2026-10-17: [8.0.16-security](https://github.com/juce-framework/JUCE/releases/tag/8.0.16-security), published 2026-10-13, adds malformed-String protection and is the pinned version already used here. Using the maintained security backport avoids an unqualified major-framework migration during DSP evaluation.
